一、这是什么
  一个可运行的招聘流程系统。覆盖：发布岗位 → AI 解析简历 → 人工核对 →
  人工推荐 → 部门反馈（同意/拒绝/需补充）→ 面试官录用决定 → 已入职候选人
  → 用人结果回评。
  技术栈：Node.js + Express + SQLite（node:sqlite，无需装数据库）+ 原生前端（零构建）。

二、30 秒跑起来
  环境要求：Node.js ≥ 22.5（需内置 node:sqlite；推荐 22.22 LTS 或更高）
  在解压后的目录里执行：

      npm install
      npm start

  然后浏览器打开 http://localhost:5173
  （想换端口：设置环境变量 PORT，例如 PORT=8080）

  说明：node_modules 未打包（体积原因），npm install 会从公网拉 3 个依赖：
  express、multer、pdfjs-dist。全程无需编译。

三、已经带了演示数据，不用初始化
  包内 storage/recruitment.db 是一份可直接登录的演示库：
    · 2 个在招岗位（AI应用全栈工程师 / 大模型算法工程师）
    · 21 份应聘记录、6 条推荐、2 条入职、5 条部门反馈
    · 3 份岗位画像解读、2 条追问与解答
    · 11 条平台配置、105 条审计记录
  也就是说：npm start 后直接能登录、能看各工作台、能走流程，不需要跑种子脚本。

  想从空白库重建（会清空现有数据、需联网调用大模型）：
      npm run seed

五、大模型 Key 需要你自己配
  出于安全考虑，交付包内的 API Key 已清空。
  方式一：在项目根目录新建 .env，写入
      LLM_BASE_URL=https://api.deepseek.com
      LLM_MODEL=deepseek-flash
      LLM_API_KEY=你的Key
  方式二：直接用环境变量传入同名变量。

  不配 Key 也能启动和浏览：AI 解析/岗位画像解读/追问草稿会调用失败并给出提示，
  其余流程（人工核对、推荐、反馈、录用、回评）不受影响。

六、验证系统是否合规
      npm test
  26 项红线与权限用例，跑在临时库上，不会污染演示数据。
  覆盖：账号状态、岗位隔离、跨部门隔离、低分不淘汰、自动淘汰锁定、
  追问权限、录用决定权限、审计留痕。

七、几条必须知道的产品约束（写在代码里，不是口头承诺）
  1. AI 只辅助初筛，绝不自动淘汰候选人。
     配置项 auto_eliminate_enabled 状态为 locked、值为 false，接口直接拒绝开启。
  2. 分数只用于排序与人工判断，不作过滤条件。
     配置项 score_threshold_enabled 值为 false、状态 pending（待确认）。
  3. AI 可以起草推荐理由，但提交必须由招聘专员本人点击，且要填理由与差距。
  4. 权限是「能力点 × 数据范围」双维度：专员只能看自己负责岗位的候选人材料。

八、目录说明
  server/          后端（入口、表结构、鉴权、路由、大模型、PDF 抽取、种子、用例）
  web/             前端（单文件 ESM + 原生 CSS，无构建步骤）
  data/            原始素材：岗位需求 docx、30 份脱敏 PDF 简历（按岗位分目录）
  storage/         运行期数据：SQLite 数据库、上传的简历原件
  deploy/          Windows 服务器一键部署脚本与说明
  openspec/        规格文档（proposal / specs / design / tasks）
  交付/            交付汇报 PPT
